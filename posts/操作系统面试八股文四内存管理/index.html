操作系统面试八股文（四）——内存管理

操作系统面试八股文（四）——内存管理

内存管理概述

内存管理的功能

  1. 内存分配与回收：为进程分配内存空间，进程结束后回收
  2. 地址转换：将逻辑地址转换为物理地址
  3. 内存保护：防止进程间互相干扰
  4. 内存扩充：通过虚拟内存技术，逻辑上扩充内存容量

程序的编译与链接

源程序到运行的完整过程：

阶段说明地址
编译源代码 → 目标模块逻辑地址（从0开始）
链接目标模块 + 库 → 装入模块逻辑地址（统一编址）
装入装入模块 → 内存物理地址

链接的三种方式：

  • 静态链接：装入前将所有模块链接成一个整体
  • 装入时动态链接：装入内存时链接
  • 运行时动态链接：运行时需要才链接（如动态库DLL）

装入的三种方式：

  • 绝对装入：编译时确定物理地址（单道程序环境）
  • 可重定位装入（静态重定位）：装入时将逻辑地址转换为物理地址，装入后不可移动
  • 动态运行时装入（动态重定位）：装入时不转换，运行时才转换，需要重定位寄存器支持

面试高频问：静态重定位和动态重定位的区别？

  • 静态重定位：装入时一次完成地址转换，之后不能移动，不能实现内存紧凑
  • 动态重定位：运行时借助重定位寄存器转换地址，程序可以在内存中移动

连续分配管理方式

单一连续分配

内存分为系统区和用户区，用户区只能有一道程序。

  • 优点：简单、无外部碎片
  • 缺点：只能单用户单任务、有内部碎片、内存利用率极低

固定分区分配

将用户空间划分为若干固定大小的分区，每个分区装入一道作业。

  • 优点：支持多道程序
  • 缺点：内部碎片、分区大小固定不灵活

内部碎片 vs 外部碎片：

  • 内部碎片：分配给进程的内存大于进程所需，分区内部的浪费
  • 外部碎片：内存中空闲空间总量足够，但不连续，无法满足大进程需求

动态分区分配

不预先划分，根据进程需要动态分配。

动态分区分配算法：

算法思想优点缺点
首次适应（First Fit）按地址递增查找，第一个够大的高地址空间保留大空闲区低地址产生很多小碎片
最佳适应（Best Fit）找最小的够大的分区外部碎片最小（理论上）产生很多难以利用的小碎片
最坏适应（Worst Fit）找最大的分区分配减少小碎片大分区被用完，大进程无法装入
邻近适应（Next Fit）从上次查找位置开始找避免低地址小碎片高地址大分区也被用完

面试必考：首次适应算法通常是最好的。为什么？

  • 首次适应按地址顺序查找，倾向于使用低地址空闲区，保留高地址大空闲区
  • 最佳适应看似最优，实际上会产生大量极小的外部碎片
  • 最坏适应会快速消耗大空闲区

外部碎片的解决——紧凑（Compaction）：

  • 将所有进程向一端移动，合并空闲区
  • 需要动态重定位支持（移动后修改重定位寄存器）
  • 开销大

分页存储管理

分页的基本概念

将内存空间分为大小相等的块（物理块/页框/Page Frame），将进程的逻辑地址空间也分为大小相等的页（Page）。

  • 页面（页）：进程逻辑空间的划分单位
  • 页框（物理块）：物理内存的划分单位
  • 页面大小：通常为4KB（2^12），必须是2的幂

进程的最后一页可能不满，产生页内碎片（内部碎片的一种）。

页表

每个进程有一张页表，记录页号到物理块号的映射。

页号块号
05
13
28
……

地址转换：

  • 逻辑地址 = 页号P + 页内偏移W
  • 物理地址 = 块号 × 页面大小 + 页内偏移W

如果页面大小为4KB（2^12），逻辑地址为32位：

  • 页号 = 逻辑地址的高20位
  • 页内偏移 = 逻辑地址的低12位

基本地址变换机构

地址转换过程：

  1. 从逻辑地址中提取页号P和页内偏移W
  2. 比较页号P和页表长度M，若P ≥ M则越界中断
  3. 查页表：页表始址 + P × 页表项长度 → 找到对应页表项
  4. 取出物理块号b
  5. 物理地址 = b × 页面大小 + W

注意：每次访存都需要两次访问内存（一次查页表，一次访问目标单元），速度太慢！

快表TLB（⭐⭐⭐⭐⭐）

TLB（Translation Lookaside Buffer） 是页表的高速缓存，又称联想寄存器或快表。

地址转换流程：

  1. CPU给出逻辑地址，提取页号P
  2. 同时查询TLB和页表（TLB在CPU内部，速度极快）
  3. 若TLB命中 → 直接得到块号，只需一次访存
  4. 若TLB未命中 → 查内存中的页表，得到块号，并将该页表项写入TLB

面试高频问：TLB的命中率对性能影响很大。

  • TLB命中率通常可达90%以上
  • 有效访存时间 = 命中率 × (TLB访问时间 + 内存访问时间) + (1-命中率) × (TLB访问时间 + 2 × 内存访问时间)
  • 由于TLB访问时间远小于内存访问时间，通常简化为： 有效访存时间 ≈ 命中率 × 1次访存 + (1-命中率) × 2次访存

多级页表

问题：当逻辑地址空间很大时，页表可能非常大，必须连续存放，占用大量内存。

解决方案：将页表再分页，形成多级页表。

两级页表：

  • 页目录表（外层页表）：一级索引
  • 页表（内层页表）：二级索引

逻辑地址结构：| 一级页号 | 二级页号 | 页内偏移 |

为什么多级页表能节省空间？

  • 一级页表必须常驻内存
  • 二级页表按需创建，不需要的页表不必存在
  • 对于大部分程序，实际使用的地址空间很稀疏，大部分二级页表不必创建

注意：多级页表增加了访存次数。n级页表需要n+1次访存（n次查页表 + 1次访问目标）。

反置页表

传统页表按页号索引，每个进程一张。反置页表按物理块号索引，整个系统只有一张。

  • 优点：页表大小只与物理内存大小有关，与逻辑地址空间无关
  • 缺点：查找需要哈希表辅助，否则要遍历整个表

分段存储管理

分段的基本概念

按照程序自身的逻辑关系将地址空间分为若干段，每段有段名和段长。

特点分页分段
划分依据物理大小（系统行为）逻辑意义（用户行为）
大小固定（页面大小相同）不固定（由程序逻辑决定）
地址空间一维（页号自动计算）二维（需指定段号+段内偏移）
碎片内部碎片外部碎片

段表与地址变换

段表记录段号到段起始地址和段长的映射。

段号段长基址
01K40K
14K80K
22K120K

地址变换：

  1. 从逻辑地址中提取段号S和段内偏移W
  2. 若S ≥ 段表长度 → 越界中断
  3. 查段表取出段长C和基址B
  4. 若W ≥ C → 越界中断（段内偏移不能超过段长）
  5. 物理地址 = B + W

分段有两次地址越界检查：段号越界和段内偏移越界。分页只有一次页号越界检查。

分页与分段的对比（⭐⭐⭐⭐⭐）

维度分页分段
目的提高内存利用率方便编程、信息共享和保护
大小由系统确定，固定由程序确定，不固定
地址空间一维二维
碎片内部碎片外部碎片
共享不方便方便（按逻辑段共享）
信息保护困难方便（按逻辑段设置权限）

段页式管理

结合分段和分页的优点：

  • 先分段后分页：用户程序先按逻辑分段，每段内再分页
  • 地址结构：| 段号 | 页号 | 页内偏移 |
  • 需要段表和页表两级查表

地址变换过程：

  1. 查段表 → 得到页表始址
  2. 查页表 → 得到物理块号
  3. 物理地址 = 块号 × 页面大小 + 页内偏移

段页式管理需要三次访存（段表 + 页表 + 目标），使用TLB可减少访存次数。

虚拟内存

虚拟内存的基本概念

虚拟内存是基于局部性原理，在程序执行时只将当前需要的部分装入内存，其余留在外存。当访问的信息不在内存时，由操作系统将所需信息从外存调入内存。

局部性原理：

  • 时间局部性：最近访问的信息很可能再次被访问（循环）
  • 空间局部性：访问某存储位置后，附近的位置也很可能被访问（顺序执行）

虚拟内存的实现方式

方式基于分页基于分段
请求分页✅ 最常用—
请求分段—较少使用
请求段页式—复杂，极少使用

虚拟内存的特征：

  1. 多次性：作业无需一次全部装入，允许分成多次调入
  2. 对换性：作业运行中允许换入换出
  3. 虚拟性：逻辑上扩充内存容量

注意：虚拟内存的"三次性"（多次性、对换性、虚拟性）与传统内存管理的"一次性"对立。

请求分页管理

在基本分页基础上增加调页功能和页面置换功能。

新增的页表项字段：

字段说明
页号页面编号
块号对应的物理块号
状态位P是否在内存中（0/1）
访问字段A记录最近访问时间或访问次数（供置换算法使用）
修改位M页面调入内存后是否被修改（决定换出时是否写回外存）
外存地址页面在外存上的位置

缺页中断处理流程：

  1. CPU访问某页，查页表发现状态位P=0（不在内存）
  2. 发出缺页中断，转入缺页中断处理程序
  3. 若内存有空闲块 → 从外存调入该页，更新页表
  4. 若内存无空闲块 → 按页面置换算法选择一页换出：
    • 若换出页修改位M=1 → 写回外存
    • 若换出页修改位M=0 → 直接丢弃（外存有副本）
  5. 从外存调入所需页面，更新页表
  6. 返回被中断的指令重新执行

缺页中断 vs 一般中断：

  • 缺页中断在指令执行期间产生（一般中断在指令执行完后检测）
  • 一条指令可能产生多次缺页中断（如跨页的指令操作）

页面置换算法（⭐⭐⭐⭐⭐）

当内存满时，需要选择一个页面换出，这个选择策略就是页面置换算法。

OPT——最佳置换算法

思想：淘汰以后最长时间不再被访问的页面。

  • 优点：缺页率最低（理论最优）
  • 缺点：无法实现（需要预知未来的访问序列）
  • 作用：作为其他算法的性能评价标准

FIFO——先进先出置换算法

思想：淘汰最早进入内存的页面。

  • 优点：实现简单
  • 缺点：性能差；可能产生Belady异常

Belady异常：分配的物理块数增加，缺页次数反而增加！ 这是FIFO算法特有的异常，其他算法不会出现。

LRU——最近最久未使用置换算法

思想：淘汰最近最长时间没有被访问的页面（向前看）。

  • 优点：性能接近OPT，是实际中性能最好的算法
  • 缺点：实现开销大（需要硬件支持，记录每个页面的访问时间戳或维护栈）

LRU的实现：

  • 时间戳法：每次访问更新时间戳，淘汰时找最小的
  • 栈法：维护一个访问栈，访问某页时移到栈顶，淘汰栈底

面试高频问：LRU和LFU的区别？

  • LRU（Least Recently Used）：淘汰最近最久未使用的——基于时间
  • LFU（Least Frequently Used）：淘汰最近使用频率最低的——基于频率

CLOCK——时钟置换算法

思想：为每页设置一个访问位，将页面组织成循环链表（像时钟），扫描时：

  • 访问位=0 → 淘汰该页
  • 访问位=1 → 将访问位置0，继续扫描

改进型CLOCK算法：同时考虑访问位A和修改位M：

(A, M)含义优先淘汰
(0, 0)最近未访问，未修改✅ 第一轮淘汰
(0, 1)最近未访问，已修改第二轮淘汰
(1, 0)最近访问过，未修改第三轮淘汰
(1, 1)最近访问过，已修改最后淘汰

改进型CLOCK需要最多四轮扫描，但减少了I/O操作（优先淘汰未修改的页面）。

页面置换算法对比

算法性能实现难度Belady异常
OPT最好无法实现无
FIFO最差最简单有
LRU很好较难无
CLOCK较好简单无

页面抖动与工作集

抖动（Thrashing）：频繁发生缺页中断，大部分时间用于页面的换入换出，系统效率急剧下降。

产生原因：分配给进程的物理块太少，进程频繁缺页。

工作集（Working Set）：在某段时间间隔（窗口）内，进程实际访问的页面集合。

预防抖动的方法：确保分配给进程的物理块数 ≥ 工作集大小。

页面分配策略

策略说明优缺点
固定分配每个进程分配固定数量的物理块简单但可能不合理
可变分配根据进程需要动态调整物理块数灵活但管理复杂
置换范围说明
局部置换只在进程自己的物理块中选择换出
全局置换可以从其他进程的物理块中选择换出

实际系统通常采用可变分配+全局置换（如Linux）。

经典面试题

⭐⭐⭐⭐⭐ 虚拟内存是什么？为什么需要虚拟内存？

虚拟内存是一种内存管理技术，它使程序可以使用比物理内存更大的地址空间。

为什么需要：

  1. 内存不够用：程序所需内存超过物理内存
  2. 内存保护：每个进程有独立的虚拟地址空间，互相隔离
  3. 内存利用率：只加载需要的页面，减少浪费
  4. 编程方便：程序员不必关心物理内存布局

⭐⭐⭐⭐⭐ 分页和分段有什么区别？

维度分页分段
设计目标提高内存利用率满足用户需求（共享、保护）
大小固定可变
地址空间一维二维
碎片内部碎片外部碎片
信息共享不方便方便

⭐⭐⭐⭐ 页面置换算法有哪些？LRU怎么实现？

常见算法：OPT、FIFO、LRU、CLOCK

LRU实现：

  • 时间戳法：每个页面记录最近访问时间戳，淘汰时选时间戳最小的
  • 栈法：维护一个栈，每次访问将页面移到栈顶，淘汰栈底页面
  • 实际系统中，精确LRU开销太大，通常使用近似LRU（如CLOCK算法）

⭐⭐⭐⭐ 什么是Belady异常？哪个算法会出现？

Belady异常是指：分配的物理块数增加，缺页次数反而增加的现象。

只有FIFO算法会出现Belady异常。LRU和OPT属于栈算法，不会出现。

⭐⭐⭐ TLB的作用是什么？没有TLB会怎样？

TLB（快表）是页表的高速缓存。没有TLB，每次访存都需要先访问内存中的页表，再访问目标内存，访存时间翻倍。有了TLB，大部分情况下只需一次访存。

⭐⭐⭐ 缺页中断和普通中断有什么区别？

  1. 缺页中断在指令执行期间产生，普通中断在指令执行完后检测
  2. 一条指令可能产生多次缺页中断（如跨页操作）
  3. 缺页中断返回后重新执行该指令，普通中断返回后执行下一条指令
